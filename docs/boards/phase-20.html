Creating one makes the database page with a Name and a Status property, and one empty row. Sidebar glyph: a small table. Change type does not offer Database (a page with text becomes one only by choosing so in its menu, which keeps its text above the table).

Data model (for approval with the boards)

Where: the index doc, like titles and tags, so it is sealed and syncs; nothing new on the server.
Database: a note with kind: "database" and a nested db map: props (a Y.Array of {id, name, type, options}, types text, number, select, date, checkbox; options carry a label and one of six tints), sort ({prop, dir}), filters (a list of {prop, op, value}) and hidden (property ids not shown).
Rows: the database's child pages, any kind. Each row note gets a cells Y.Map keyed by property id, so two devices editing different cells merge; the same cell is last writer wins. The title is the built-in first column.
Deleting a property hides it for good in the table but leaves the values in cells, so an undo or another device's late edit cannot break anything.
Shown rows: computed on the device (databaseRows(notes, db), pure, tested), like search and backlinks. A row moved out of the database keeps its cells but they are not shown until it is moved back.
Spike first: pure functions in packages/sync/src/database.ts with tests (create, add property, set cell, sort, filter, concurrent cell edits, deleted property) before any screen.
Left out on purpose: formulas, relations, rollups, multiple views, grouping, drag-to-reorder columns, CSV export of the table.
